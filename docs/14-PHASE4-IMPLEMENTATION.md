# Phase 4 — Multilingual Query Understanding & IR Evaluation

## Scope and acceptance boundary

This iteration extends the Phase 3 lexical BM25 service with a small, auditable query planner and deterministic relevance evaluation. It does not introduce vector search, LLM rewriting, or production-validated relevance improvements.

## Query pipeline

Raw query → control/length validation → Unicode NFKC → quote-aware bounded tokenization → typed filters → script/language diagnostics → intent heuristic → optional suggestion/curated expansion → typed OpenSearch bool DSL → BM25 → analysis and results.

Hard limits: 200 original characters, 32 query atoms, 8 phrases, 8 excluded terms, 4 expansions, max 20 results and offset max 200.

## Multilingual logic

Chinese: diagnostic maximal-match vocabulary with overlapping character bigrams for unknown Han runs; the actual search tokens are generated by OpenSearch CJK analyzers. English: preserve technical tokens C++, C#, .NET, package names and identifiers, while OpenSearch handles English stemming. Mixed: preserve both scripts, do not automatically force a language filter. Unknown terms are passed through unmodified.

Intent is a deterministic heuristic (informational, tutorial, comparison, navigation, troubleshooting). It is not a trained model.

## Grammar

| Operator | Semantics |
|---|---|
| Double-quoted phrase | Required exact phrase (slop zero) in one indexed field |
| -word or -quoted-phrase | Must-not search clause |
| lang:zh/en/mixed/und | Exact indexed language |
| source:ID | Exact authorized source ID |
| site:example.org | Exact indexed host, not suffix wildcard |
| after:YYYY-MM-DD | UTC from midnight, inclusive |
| before:YYYY-MM-DD | UTC to midnight, exclusive |
| rewrite_mode=suggest | Non-applied spelling suggestion returned in response |
| rewrite_mode=expand | Up to four explicit, low-weight controlled synonyms |

Quoted phrases, source/site/date and visibility/deletion safeguards do not become soft scoring signals. Contradictory filters fail validation. User OpenSearch DSL, unbounded regexp, wildcard-leading expressions and only-negative queries are not accepted.

## HTTP and CLI

- GET /v1/query/analyze?q=... — pure query diagnostics, no search backend request.
- GET /v1/search?q=...&rewrite_mode=suggest — BM25 response plus analysis.
- python -m search_engine.cli analyze "OpenSearch 中文分词" — operator CLI.
- python -m search_engine.cli search "inverted index" --rewrite-mode expand — opt-in expansion.

## Stanford IIR chapter 8 measurement

Input: JSON array of rows {query_id,language,judgments:{document_id:integer_0_3},results:[ranked_doc_ids]}. Output: per-language and overall macro metrics.

- nDCG@10: logarithmically discounted exponential gain (2^grade - 1), normalized by ideal DCG.
- Precision@10: known relevant results in top 10 divided by 10.
- Recall@100: known relevant results retrieved in first 100 over all known relevant; exclude queries with no known relevant documents from the recall mean.
- MRR@10: reciprocal of first known relevant result rank within first 10.
- judged_fraction: top-k fraction of results with explicit judgments, highlighting incomplete relevance pools.

Unjudged hits are scored zero by policy, not declared objectively irrelevant. Reject duplicate ranked document IDs and invalid grades/duplicate query IDs.

Reproducible demo: PYTHONPATH=src python scripts/evaluate_relevance.py --input tests/fixtures/relevance-demo.json

The demo is SYNTHETIC and should never be used to claim user relevance gains. Before quality assertions: collect >=100 human-graded zh, en, mixed queries each; freeze corpus/index/analyzers; split development/holdout; report per-intent regressions and confidence intervals.

## Verification

Unit tests cover grammar, Unicode, quote/negation semantics, exact host/language/source/date filters, bad inputs, rewrite non-application, hard filters, nDCG/Recall/MRR math and multilingual aggregation. CI re-runs Phase 1–3 tests, builds the Docker image, checks Compose, and runs real OpenSearch analyzer/phrase/site-filter/tombstone/rebuild checks.

## Deferred

Learned Chinese segmentation, term-frequency spelling correction, intent classifier training, high-recall semantic retrieval, vector/HNSW, rerankers, production ACLs, human judgments, production latency/load and long-tail query analysis.
